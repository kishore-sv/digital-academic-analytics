# Model 3 — Student At-Risk Detection / Risk Assessment

## 1. Purpose

Identify students who may require academic intervention based on current academic indicators.

**Question answered:** "Which students are currently at risk and may need attention?"

## 2. Why Risk Assessment Is Needed

The ERP system needs early-warning capability to flag students before final outcomes are known. Model 3 provides transparent, explainable risk scoring without requiring historical at-risk labels.

## 3. Implementation Type

**Rule-based weighted scoring engine** — not a trained ML model.

The UCI dataset does not contain reliable historical labels such as `AT_RISK` / `NOT_AT_RISK` or intervention outcomes. Training an ML classifier would require inventing labels, which would make the model learn an arbitrary rule rather than genuine historical patterns.

## 4. Inputs

| Field | Type | Required | Valid Range | Meaning |
|-------|------|----------|-------------|---------|
| absences | int | yes | ≥ 0 | Number of school absences |
| G1 | float/int | yes | 0–20 | First period grade |
| G2 | float/int | yes | 0–20 | Second period grade |
| failures | int | yes | ≥ 0 | Number of past class failures |
| studytime | int | yes | 1–4 | Weekly study time (1=very low, 4=very high) |

**Derived:** `performance_trend = G2 - G1`

**Explicitly excluded:** `G3` (final grade) — tested to confirm risk results are independent of G3.

## 5. Risk Factors

Each factor is mapped to a tier: **0 = LOW**, **1 = MEDIUM**, **2 = HIGH**.

### Absence Risk (weight: 25)

| absences | Tier |
|----------|------|
| ≤ 4 | LOW (0) |
| 5–9 | MEDIUM (1) |
| ≥ 10 | HIGH (2) |

### Performance Risk (weight: 30)

Based on `G2`:

| G2 | Tier |
|----|------|
| ≥ 12 | LOW (0) |
| 10–11 | MEDIUM (1) |
| < 10 | HIGH (2) |

### Trend Risk (weight: 20)

Based on `G2 - G1`:

| Trend | Tier |
|-------|------|
| > 0 (improving) | LOW (0) |
| = 0 (stable) | MEDIUM (1) |
| < 0 (declining) | HIGH (2) |

**Note:** Trend thresholds are hardcoded in `risk_engine.py`, not in the JSON configuration.

### Failure Risk (weight: 15)

| failures | Tier |
|----------|------|
| 0 | LOW (0) |
| 1 | MEDIUM (1) |
| ≥ 2 | HIGH (2) |

### Study-Time Risk (weight: 10)

| studytime | Tier |
|-----------|------|
| ≥ 3 | LOW (0) |
| 2 | MEDIUM (1) |
| 1 | HIGH (2) |

## 7. Thresholds

### Risk level boundaries

| Level | Condition |
|-------|-----------|
| LOW | risk_score ≤ 30 |
| MEDIUM | 30 < risk_score ≤ 60 |
| HIGH | risk_score > 60 |

### Factor thresholds (in JSON)

See `ml/models/model_3/risk_engine_config.json` for `absence`, `performance`, `failures`, `studytime`, and `risk_level` threshold values.

## 8. Risk Calculation

```
risk_score = (absence_tier / 2) × 25
           + (performance_tier / 2) × 30
           + (trend_tier / 2) × 20
           + (failure_tier / 2) × 20
           + (studytime_tier / 2) × 10
```

- Tier 0 → 0 points; tier 1 → half weight; tier 2 → full weight
- Range: 0–100
- Example (all HIGH): 25 + 30 + 20 + 15 + 10 = 100

### Risk indicators (human-readable)

Generated by `get_risk_indicators()` based on configured thresholds:

- High Absence / Moderate Absence
- Low Current Performance / Moderate Current Performance
- Declining Performance / Stable Performance
- Multiple Previous Failures / Previous Failure
- Low Study Time / Moderate Study Time

**Known behavior:** The indicator logic checks `g2 < medium_min` before `g2 < low_min`, so "Moderate Current Performance" may not trigger for G2 in the 10–11 range. This matches the notebook implementation.

## 11. JSON Configuration

**Path:** `ml/models/model_3/risk_engine_config.json`

```json
{
  "weights": { "absence": 25, "performance": 30, "trend": 20, "failure": 15, "studytime": 10 },
  "thresholds": {
    "risk_level": { "low_max": 30, "medium_max": 60 },
    "absence": { "low_max": 4, "medium_max": 9 },
    "performance": { "low_min": 12, "medium_min": 10 },
    "failures": { "low": 0, "medium": 1, "high_min": 2 },
    "studytime": { "high": 1, "medium": 2, "low_min": 3 }
  }
}
```

The production `risk_engine.py` reads this JSON as the source of truth for weights and factor thresholds. Trend logic is hardcoded (not in JSON).

## 12. Inference Flow

```
Input dict (5 fields)
    → validate_risk_input()
    → load risk_engine_config.json
    → calculate_risk() — tier each factor, compute weighted score
    → get_risk_indicators() — human-readable strings
    → structured response
```

Entry point: `src/model_3/risk_engine.py` → `assess_student_risk(input_data)`

## 13. Limitations

- No formal ML evaluation (no ground-truth at-risk labels)
- Weights and thresholds are manually configured, not learned from data
- Trend scoring logic is not configurable via JSON
- Trained/validated only against UCI dataset distribution
- Indicator string logic has the moderate-performance edge case noted above

## 14. Future Improvements

- Make trend thresholds configurable in JSON
- Validate against institutional intervention records when available
- Consider converting to ML model if labeled at-risk data becomes available
- Fix indicator ordering for moderate performance labels
